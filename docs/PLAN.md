# Платформа онлайн-викторин — план проекта

> Рабочее название: **QuizRoom** (поменяем, когда выберем дизайн).
> Тема из задания: «Создание викторин, прохождение в реальном времени с другими игроками, таблица лидеров. Сложность: real-time взаимодействие, таймер на вопросы».

---

## 1. Видение продукта

Автор собирает викторину в редакторе, запускает игру и показывает на большом экране PIN-код. Игроки заходят с телефона по PIN и нику (регистрация не нужна), отвечают на вопросы на время, после каждого вопроса видят правильный ответ и своё место, в конце — подиум и итоговая таблица.

**Целевая аудитория:** преподаватели и студенты (пары, кураторские часы), организаторы студенческих мероприятий, команды для тимбилдинга.

**Аналоги для анализа конкурентов:** Kahoot!, Quizizz, Mentimeter, Myquiz, Wordwall.
**Наше отличие (черновик УТП):** бесплатно, без регистрации для игроков, на русском, работает в слабой сети (переподключение без потери очков).

### 2.1. Банк необычных механик (с холста дизайна, варианты D–I)

Это не обязательный объём, а набор «фишек», из которых выберем 1–2 для УТП. Оценка сложности: S — до 2 дней, M — неделя, L — больше недели.

| Механика | Суть | Сложность | Что меняется в системе |
|---|---|---|---|
| **Новые типы вопросов** (G) | «Угадай число» (очки за близость, точное попадание ×2), «Расставь по порядку» (очки за каждый элемент на месте) | S–M | `questions.type += number, order`; поля `answer_number`, `tolerance`; `player_answers.value jsonb` |
| **Лобби-аквариум** (H) | Игрок собирает существо (форма, цвет, глаза), оно плавает на экране ведущего; кнопка «Помахать» | S | `players.avatar jsonb`; WS-событие `lobby:wave` |
| **Итоговая «газета»** (I) | Карточка с результатом игрока: поделиться в Telegram или сохранить картинкой | S–M | Рендер картинки на сервере (Pillow/Playwright) или canvas на клиенте; Open Graph-превью ссылки |
| **Отчёт преподавателя** (I) | Тепловая карта «ученик × вопрос», самые трудные вопросы, экспорт в Excel, «повторить только ошибки» | M | Агрегаты по `player_answers`; эндпоинт `/sessions/{id}/report`; генерация xlsx |
| **Гонка** (D) | Вместо таблицы — трасса: верный ответ = шаг, быстрый = два; бонусы 50/50, ×2, «Лёд» | M | `game_mode = race`; бонусы в Redis (`powerups:{player}`); WS `powerup:use` |
| **Биржа** (E) | Перед ответом игрок ставит 10–100% очков; ошибка — минус ставка; ведущий видит «стакан» ставок | M | `player_answers.wager`; своя формула очков; живая агрегация ставок |
| **Территории** (F) | Командный режим: голосование внутри команды, капитан утверждает, команды захватывают гекс-карту | L | Таблица `teams`, `players.team_id`, роль капитана; WS-комнаты команд; состояние карты |

**Решение (25.10.2026): в MVP берём G + H + отчёт из I.** Визуальный стиль под них — «Риф», см. [DESIGN.md](DESIGN.md). Режимы D/E — только если останется время в спринте 5; F и «газета» — в «План развития» на защите.

### Игровой движок (самая сложная часть)

Состояния комнаты: `lobby → question → reveal → … → finished` (таблица лидеров показывается на разборе).

- **Источник истины — сервер.** Сервер присылает `question:start` с `endsAt` (время сервера, мс) и `serverNow`; клиент считает смещение часов и рисует таймер от `endsAt`. Время ответа фиксируется в момент получения сообщения; после `endsAt` сервер даёт 300 мс на доставку и дальше ответ отклоняет.
- **Закрытие вопроса:** по таймеру (asyncio-задача на комнату) или досрочно, когда ответили все. Игрока с оборвавшейся связью ждём до 8 секунд.
- **Очки:** верный ответ = `round(1000 × (1 − 0.5 × t / T))`, где t — время ответа, T — лимит (от 500 до 1000 очков). Неверный — 0.
  - *Угадай число:* `база × max(0, 1 − |ответ − правильный| / допуск)`, точное попадание ×2 (если включено).
  - *По порядку:* `1000 × доля элементов на своём месте × коэффициент скорости`; верным считается только полностью правильный порядок.
  - Равные очки делят место: 1, 2, 2, 4.
- **Лидерборд:** считается в памяти комнаты, топ-10 отдаём на разборе каждого вопроса.
- **Переподключение:** игрок получает `playerToken`; при реконнекте сервер шлёт снапшот текущего состояния (вопрос, остаток времени, очки).
- **Идемпотентность:** один ответ на вопрос от игрока (повторы игнорируются).

## 6. Модель данных

```
users          (id, email UQ, username, password_hash, created_at)
quizzes        (id, owner_id → users, title, description, is_public, created_at, updated_at)
questions      (id, quiz_id → quizzes, position, text, type[single|number|order],
                time_limit,
                number_answer NULL, number_min NULL, number_max NULL,
                number_tolerance NULL, number_exact_bonus bool)        -- для type=number
answer_options (id, question_id → questions, position, text, is_correct)
                -- single: is_correct у одного; order: position = правильный порядок
game_sessions  (id, quiz_id → quizzes, host_id → users, pin, title, status, started_at, finished_at,
                snapshot json,          -- копия вопросов на момент запуска + какие показали и кто мог ответить
                parent_session_id NULL)                                -- «повтор только ошибок»
players        (id, session_id → game_sessions, user_id → users NULL, nickname, token,
                avatar json {shape, color, eyes}, final_score, final_rank, reconnects int)
player_answers (id, player_id → players, question_index,       -- индекс в snapshot
                value json,             -- {option_id} | {number} | {order: [option_id…]}
                is_correct, response_ms, points)  UQ(player_id, question_index)
```

## 7. API (черновик; итоговый список — в README и Swagger на `/docs`)

**REST**
```
POST   /api/auth/register            POST /api/auth/login        GET /api/auth/me
GET    /api/quizzes?mine=1&search=   POST /api/quizzes
GET    /api/quizzes/{id}             PATCH /api/quizzes/{id}     DELETE /api/quizzes/{id}
POST   /api/quizzes/{id}/questions   PATCH/DELETE /api/questions/{id}
POST   /api/quizzes/{id}/copy
POST   /api/sessions                 (запустить игру → pin)
GET    /api/sessions/{pin}/exists    (проверка PIN перед входом)
POST   /api/sessions/{pin}/join      (ник → playerToken)
GET    /api/sessions/history         GET /api/sessions/{id}/report
```

**WebSocket `/ws/game/{pin}`**
```
клиент → сервер: host:start, host:next, host:end, player:wave,
                 player:answer {questionId, value: {optionId} | {number} | {order: [ids]}}
сервер → клиент: lobby:update {players + avatar}, lobby:wave {playerId},
                 question:start {question, endsAt, serverNow},
                 answer:ack, question:progress {answered, total},
                 question:reveal {correct, stats, yourPoints},
                 leaderboard {top, you}, game:finished {podium}, state:snapshot
```

## 8. Ключевые пользовательские сценарии

1. **Создание:** главная → «Создать викторину» → нет входа → модалка регистрации → редактор → добавить вопросы → «Сохранить».
2. **Проведение:** «Мои викторины» → «Запустить» → экран лобби с PIN и QR → игроки подключаются → «Начать» → вопросы → подиум.
3. **Игра:** открыть сайт на телефоне → ввести PIN → ввести ник → ждать в лобби → отвечать → видеть «верно / неверно, +840» и место → итог.

## 9. User stories (первые 10, с критериями приёмки)

| # | История | Критерии приёмки |
|---|---|---|
| 1 | Как автор, я хочу зарегистрироваться по email, чтобы сохранять викторины | Валидация email/пароля; повторный email → ошибка; после регистрации — вход |
| 2 | Как автор, я хочу нажать «Создать викторину», чтобы перейти к редактору вопросов | Неавторизованному показывается модалка входа; после входа открывается редактор |
| 3 | Как автор, я хочу добавлять вопросы с 2–4 вариантами и отметкой верного | Нельзя сохранить вопрос без верного ответа; порядок меняется перетаскиванием |
| 4 | Как автор, я хочу задать время на каждый вопрос | Значения 5–120 с; по умолчанию 20 с |
| 5 | Как ведущий, я хочу запустить игру и получить PIN | PIN из 6 цифр, уникален среди активных игр; показывается QR |
| 6 | Как игрок, я хочу войти по PIN и нику без регистрации | Неверный PIN → понятная ошибка; занятый ник → предложение другого |
| 7 | Как ведущий, я хочу видеть, кто подключился, в реальном времени | Список обновляется < 1 с; можно удалить игрока |
| 8 | Как игрок, я хочу видеть таймер и успеть ответить | Таймер синхронизирован с сервером (расхождение < 300 мс); после 0 ответ не принимается |
| 9 | Как игрок, я хочу после вопроса видеть, прав ли я и сколько очков | Показ «верно/неверно», очки, текущее место |
| 10 | Как ведущий, я хочу видеть таблицу лидеров после каждого вопроса и подиум в конце | Топ-5, анимация смены мест, итог сохраняется в историю |

**Как истории приняты (9 ноября).** Полностью по критериям готовы 1, 5 и 9. Остальные работают с отличиями:
- **2** — вместо модального окна отдельная страница входа; после входа возвращает в редактор.
- **3** — порядок вариантов меняется стрелками (это работает и с клавиатуры), перетаскивания нет.
- **4** — в редакторе 10, 20, 30 или 60 с, по умолчанию 20; API принимает 5–120.
- **6** — занятый ник даёт подсказку добавить букву или цифру, готовое имя не предлагаем.
- **7** — удалять игроков можно только в лобби; добавлена кнопка «Закрыть вход».
- **8** — таймер идёт от серверного `endsAt` с поправкой на часы; расхождение на реальных устройствах ещё не измеряли.
- **10** — на разборе топ-10, анимации смены мест нет; итог сохраняется в историю.

## 11. Качество, CI/CD, Git

- Ветки: `main` (защищена) ← `dev` ← `feature/<номер>-<кратко>`; merge только через PR с ревью Team Lead и зелёным CI.
- CI (GitHub Actions): ruff + mypy, eslint + tsc, pytest, vitest, сборка Docker-образов; на `main` — автодеплой.
- Тесты: unit на подсчёт очков и переходы состояний комнаты, integration на REST и WS, e2e «ведущий + 3 игрока проходят викторину», нагрузка k6.
- Чек-лист ручного регресса перед каждым релизом.

| Несколько воркеров API | Состояние в Redis, рассылка через pub/sub (или один воркер для MVP) |
| Не успеваем | Жёстко держим Must, Could переносим в «План развития» на защите |
